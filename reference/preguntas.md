# Banco de preguntas

Hacer solo las que el pedido, `PRODUCT.md` o `DESIGN.md` no responden. Máximo 4 por ronda. Cada pregunta con una opción recomendada primero, para que el usuario pueda aceptar rápido.

## §1 · Brief (antes de impeccable shape)

Lo que impeccable no pregunta y condiciona la construcción:

1. **Stack.** HTML/CSS estático (recomendado para una landing de una página) · Astro (varias páginas, contenido) · Next.js (app con lógica, login, datos) · el que ya tiene el proyecto.
2. **Dónde se publica.** Vercel · Netlify · GitHub Pages · todavía no sé (dejarlo listo para cualquiera).
3. **Contenido disponible.** Tengo textos y fotos · tengo textos, faltan fotos · nada todavía (usar placeholder marcado).
4. **Referencia.** Ninguna · tengo una URL (activa el paso 0).

Idioma(s) del sitio: preguntarlo solo si no se deduce del pedido.

El resto (para quién es, qué tiene que lograr, tono, alcance) lo pregunta `impeccable shape`.

## §2 · Dirección

1. **Tono en tres palabras.** Ofrecer una propuesta deducida del brief ("Leo: cálido, artesanal, directo. ¿Va?") en lugar de un menú vacío.
2. **Marca existente.** Ninguna, libre · tengo logo y colores (pedirlos) · tengo manual de marca (pedir el archivo).
3. **Lo memorable.** Un solo elemento donde se gasta la audacia: la tipografía del título · una imagen o ilustración · una interacción · el color. Proponer uno según el brief.
4. **Modo.** Claro · oscuro · los dos (más trabajo de revisión).

## §4 · Movimiento

1. **¿Hace falta?** Mínimo: solo respuestas a acciones (recomendado por defecto) · un momento orquestado (la entrada del hero o un reveal) · narrativa con scroll (más costo y más riesgo de performance).
2. **Dónde** (si eligió más que mínimo): proponer el lugar según `DESIGN.md` ("lo memorable" de §2).

## §5 · Revisión

1. **Qué se arregla ahora.** Todo lo que bloquea + importante (recomendado) · solo lo que bloquea · todo, incluidos detalles.
2. **Vara del pulido.** MVP para publicar ya · terminado (más pasadas de polish).
